# Architecture and fleet review, 2026-09-19

Scope: 39 active `edbfi` repositories (38 public and one private), including forks and nonconsumers. Workflow/source contents were read at immutable default-branch revisions. Referenced smoke scripts and current-revision Actions jobs were inspected separately. [Public revision/run evidence](review-evidence.json) records the source snapshots. This is source/run evidence, not a new execution of every application.

## Architecture and priorities

34 repositories consume shared automation; all 34 have the checked-merge helper,
and 11 have Biome repair/recovery workflows (including this repository's templates).
The small strict aggregate, explicit repository-owned commands, immutable release
references, repair credential separation and non-force publication are sound.
Keep these boundaries.

Complexity accumulated in the custom merger: request authorization, DCO/squash
construction, complete CI inventory, API collection, merging, dispatch retries
and deployments lived in one action. Recovery dynamically imported that action.
The README was an append-only release history instead of a current interface.
The Bun workflow conflated lock-root installation and validation directories,
and its cache covered unrelated sibling locks. Repair installed the app even
though it separately installed the exact official formatter.

| Priority | Change | Impact | Complexity / risk | Decision |
|---|---|---|---|---|
| P0 | Renovate executes merges; enforce required aggregate in GitHub | Restores one merge authority | Medium code; high rollout risk without rules | Implement retirement/presets; keep automerge off until migration canary |
| P1 | Shared smoke lifecycle, caller assertions | Removes duplicated unreliable process code | Medium; real subprocess tests required | Implement additive action; consumer adoption follows release |
| P1 | Independent Bun install directory and lock-scoped cache | Root, nested and workspace callers work predictably | Low; compatible default, conflicting locks now fail explicitly | Implement and run real frozen text/binary fixtures |
| P1 | Isolated Biome-only install | Avoids unrelated app/native dependency failures | Low; preserve lock and publication evidence | Implement with real formatter and credential tests |
| P1 | Recovery owns its policy and read/dispatch support | Removes coupling to retired merger; permits other owners | Medium; preserve provenance and reservation races | Implement; separate recovery tests |
| P2 | General lockfile/workspace repair resolver | Extends privileged repair beyond standalone Bun | Medium/high, no current npm/pnpm/Yarn consumer demand | RFC, defer until immutable fixtures justify support |
| P2 | Remove recovery protocol after App publication canary | Could eliminate log parsing/reservations | High without failure evidence | Defer; retain bounded recovery |

Server-side safety was checked separately: all 33 public consumers returned
“Branch not protected” and no active branch rules. The private consumer returned
an unavailable-plan response. A source `merge-policy.json` is not server-side
enforcement. Direct Renovate merging must stay disabled until the migration
prerequisites in [the guide](renovate-migration.md) are fulfilled. No repository
settings, releases, consuming files or existing untracked planning files were
changed in this review.

Four parallel interface reviews compared minimalist functions, flexible
configuration, caller-optimized commands and ports/adapters. The recommendation
combines small caller-owned commands with deep shared process supervision and a
focused read/dispatch recovery module. A plugin registry or broad application DSL
would add configuration without a demonstrated consumer need. See the linked
[merging RFC #36](https://github.com/edbfi/automation/issues/36) and
[runtime/lockfile RFC #37](https://github.com/edbfi/automation/issues/37) for
alternatives and rollout/testability decisions.

The other nine repositories are content, automation, scripts/configuration, or planning repositories rather than standalone applications: `edbfi`, `agent-rules`, `pelican-eggs`, `arrsenal-of-scripts`, `comradarr`, `skills`, `automation`, `zimuarr`, and one private planning repository. Comradarr and zimuarr explicitly state that no functional application exists; they should not be counted as missing runnable-app smoke tests.

Prioritized support improvements:

1. Centralize process lifecycle only: start command, loopback URL(s), caller-owned assertions, bounded probes, immediate child-exit detection, failure logs and process-tree cleanup. Keep install/build/database/browser ownership in consumers, so static no-lockfile docs, nested packages, backend/frontend combinations and non-Bun projects can use it.
2. Migrate the five copied static shell probes first. Four scripts and eksamen inline code repeat startup/readiness/cleanup. Their comments claim HTTP errors fail fast, but `until curl -f ...` retries every HTTP error until timeout. The loops also do not check whether the spawned process already exited, and clean up only the top-level PID.
3. Fix/remove portaler's standalone `workflow_dispatch`, or add a build producer for it. The normal required CI path is healthy; the manual entry point is not self-contained.
4. Add a semantic page assertion to obzorarr; retain zondarr's backend/proxy/SSR assertions. Add browser coverage only where app behavior warrants it.
5. Add actual launch probes for website/repo-patches, EasyHDR and wings-vpn, and establish CI for web-presentations. Keep specialized native/container checks in consumers rather than forcing them into HTTP support.

Do not diagnose current coverage from the standalone smoke Actions listing. These workflows now execute as reusable jobs within `ci`: isfuglen's latest independent smoke listing is a September 6 failure, while its September 18 current-SHA required smoke and browser jobs both succeeded.

## Implementation validation and remaining work

Local validation on macOS arm64 (Bun 1.4.2, Node 24.14.0, Python 3.14.7)
includes native RE2 loading, strict Renovate configuration and
resolved-policy tests, the required-gate/dispatch contracts, real Biome migration
and idempotence, publication races, recovery provenance/reservations and real
smoke subprocess/server failures. Bun fixtures exercise frozen root/nested/
workspace installs using both text and binary locks; missing/conflicting locks
and manifest drift fail. actionlint validates workflow/action syntax.

All application-specific commands, database setup and browser/native assertions
remain consumer-owned. Existing consumer applications were audited through
source and successful current-revision jobs, not rerun for this change. Fixture
validation cannot prove new consumer adoption, browser rendering, hosted Renovate
permissions, server-side enforcement or deployment behavior. Required protection,
the narrowly scoped hosted canary, a major release and consumer migration remain
explicit rollout work. Privileged repair support for workspace/npm/pnpm/Yarn/
binary locks remains deferred; it must not silently fall back to an install or
convert the caller's lockfile.
